# MySQL — streszczenie (Lekcje 1–4)

## Lekcja 1 — Podstawy, CREATE, INSERT

### Instalacja i start

- Instalator: [dev.mysql.com/downloads/mysql](http://dev.mysql.com/downloads/mysql) — przy instalacji ustaw hasło `root`.
- Foldery serwera: `bin` (serwer + narzędzia), `data` (bazy, logi), `examples`, `include`, `lib`, `scripts`, `share` (błędy, charsety).
- Komendy konsoli: `\q` (wyjście), `\c` (czyszczenie), `\h` (pomoc), `\. plik.sql` / `source plik.sql` (wykonanie skryptu z pliku).

### Logowanie

```bash
mysql -u username -p
mysql -h localhost -u username -p
```

### Podgląd struktury

```sql
SHOW DATABASES;
USE nazwa_bazy;
SHOW TABLES;
DESCRIBE nazwa_tabeli;
SHOW COLUMNS FROM nazwa_tabeli;
SELECT DATABASE();
```

### Tworzenie bazy i tabeli

```sql
CREATE DATABASE bazaosob;
USE bazaosob;
CREATE TABLE osoby (
  imie VARCHAR(50) NOT NULL,
  nazwisko VARCHAR(40) NOT NULL,
  PRIMARY KEY (nazwisko)
);
DROP TABLE osoby;
```

Przykład z lekcji:

```sql
CREATE TABLE dane (
  id_osoby VARCHAR(3),
  imie VARCHAR(15) NOT NULL,
  nazwisko VARCHAR(20) NOT NULL,
  email VARCHAR(50) NULL,
  ulica VARCHAR(50) NULL,
  miasto VARCHAR(50) NULL,
  data_ur DATE NULL,
  aktywny INT DEFAULT 1,
  PRIMARY KEY (id_osoby)
);
```

### Atrybuty kolumn

- `NOT NULL` — zakaz NULL.
- `AUTO_INCREMENT` — autonumerowanie, tylko z `PRIMARY KEY`.
- `PRIMARY KEY` — unikalny identyfikator, brak powtórek.
- `FOREIGN KEY` — odwołanie do PK innej tabeli.
- `UNIQUE` — brak powtórek, ale nie musi identyfikować rekordu.
- `DEFAULT` — wartość wstawiana gdy brak w `INSERT`.
- `UNSIGNED` — tylko liczby >= 0, tylko typy całkowite.
- `ZEROFILL` — dopełnianie zerami z przodu, tylko całkowite, implikuje `UNSIGNED`.

### Silniki tabel

- `MyISAM` — szybkie odczyty, brak transakcji, rzadko zmieniane dane.
- `InnoDB` — transakcje, blokowanie wierszy, foreign keys.
- Podgląd: `SHOW ENGINES\G`
- Przykład: `CREATE TABLE t (id TINYINT AUTO_INCREMENT PRIMARY KEY) TYPE=MyISAM;`

### INSERT i ładowanie z pliku

```sql
INSERT INTO dane (imie, nazwisko, email, ulica, miasto, data_ur)
VALUES ('Mariusz','Kowalski','mk@op.pl','Polna','Warszawa','1980-02-25');

LOAD DATA LOCAL INFILE 'dane.txt' INTO TABLE dane;
```

W pliku: kolumny oddzielone tabulatorem, wiersze końcem linii. Alternatywa shell: `mysqlimport --local dane dane.txt`

## Lekcja 3 — ALTER, UPDATE, DELETE, TRUNCATE, DROP, RENAME

### Struktura tabeli

```sql
ALTER TABLE dane ADD dochody DECIMAL(12,2) DEFAULT 0;
ALTER TABLE dane DROP COLUMN dochody;
ALTER TABLE klienci MODIFY nazwisko TEXT;
ALTER TABLE klienci ALTER COLUMN nazwisko TEXT;
SHOW COLUMNS FROM dane;
```

### Dane: INSERT / UPDATE / DELETE

```sql
INSERT INTO nazwa_tabeli (kolumny) VALUES (wartosci);
UPDATE dane SET aktywny = 1 WHERE nazwisko = 'Knaz';
UPDATE Customers SET ContactName = 'Alfred Schmidt', City = 'Hamburg';
DELETE FROM dane WHERE imie = 'ewa';
```

Bez `WHERE` w `UPDATE` / `DELETE` — zmienia usuwa wszystkie wiersze.

### TRUNCATE vs DELETE

```sql
TRUNCATE TABLE nazwa_tabeli;
```

- `TRUNCATE` — szybszy, kasuje + odtwarza tabelę, resetuje `AUTO_INCREMENT`, nie zwraca liczby wierszy, nie odpala triggerów `ON DELETE`, nie jest transaction-safe.
- `DELETE` — wolniejszy, wiersz po wierszu, liczy wiersze, odpala triggery.

### Usuwanie bazy / tabel, zmiana nazw

```sql
DROP TABLE osoby;
DROP TABLE IF EXISTS t1, t2;
DROP DATABASE bazaosob;
RENAME TABLE tabela1 TO tabela2;
RENAME TABLE customer TO klienci;
```

Brak `RENAME DATABASE` — aby zmienić nazwę bazy: utwórz nową + przekopiuj dump. W 5.1.7–5.1.23 istniało, usunięte z powodu ryzyka utraty danych.

## Lekcja 4 — Użytkownicy i uprawnienia

### Poziomy uprawnień

- globalny — wszystkie bazy (`mysql.user`).
- baza danych — wszystkie tabele bazy (`mysql.db`, `mysql.host`).
- tabela — wszystkie kolumny (`mysql.tables_priv`).
- kolumna — pojedyncze kolumny (`mysql.columns_priv`).
- Tożsamość to `user@host`, nie sam `user`.

### Najczęstsze przywileje

`SELECT, INSERT, DELETE, UPDATE, REPLACE, CREATE, DROP, ALTER, INDEX, CREATE TEMPORARY TABLES, LOCK TABLES, FILE, RELOAD, SHOW DATABASES, SHUTDOWN, CREATE USER, GRANT OPTION, USAGE` (= brak przywilejów), `ALL PRIVILEGES` (= wszystko poza `GRANT OPTION`).

### Tworzenie użytkownika i GRANT

```sql
CREATE DATABASE IF NOT EXISTS baza_danych;
CREATE USER 'uzytkownik'@'localhost' IDENTIFIED BY 'haslo';
GRANT ALL PRIVILEGES ON baza_danych.* TO 'uzytkownik'@'localhost';
GRANT CREATE, INSERT, DELETE, UPDATE, SELECT ON database_name.* TO 'user_name'@'localhost';
GRANT SELECT ON *.* TO 'janek'@'localhost';
FLUSH PRIVILEGES;
SHOW GRANTS FOR 'root'@'localhost';
```

### REVOKE, RENAME, hasło, usuwanie


## Lekcja 5 — Backup, import, CSV

### Backup (mysqldump) — shell, nie konsola mysql

```sql
mysqldump -u[nazwa_uzytkownika] -P[port] -p [nazwa_bazy] > backup.sql
mysqldump -u[nazwa_uzytkownika] -P[port] -p --all-databases > backup.sql
```

### Restore — shell, nie konsola mysql

```sql
mysql -u[user] -P[port] -p [baza] < zrzut_bazy.sql
mysql --host[localhost] --user[uzytkownik] -P[port] -p nazwa_bazy < plik_ze_zrzutem.sql
```

- `[user]` — użytkownik MySQL, `[port]` — port serwera, `[baza]` — baza docelowa, `zrzut_bazy.sql` — plik backupu.

### Hasło i host w jednej linii

```sql
mysqldump -h[host] -u[user] -P[port] -p[haslo] nazwa_bazy > backup.sql
mysql -h[host] -u[user] -P[port] -p[haslo] nazwa_bazy < backup.sql
```

Uwaga: brak spacji po `-h`, `-u`, `-p`. Wariant `-p[hasło]` tylko do skryptów, w interakcji samo `-p`.

### Import CSV — przykład DZIALKI.TXT

- Separator pól `;`, pierwszy wiersz tytułowy do pominięcia.
- Tabela `dzialki` + dodatkowe `id` jako PK.

```sql
LOAD DATA LOCAL INFILE 'sciezka/DZIALKI.TXT'
INTO TABLE dzialki
FIELDS TERMINATED BY ';'
LINES TERMINATED BY '\r\n'
IGNORE 1 LINES
(numer, powierzchnia, przeznaczenie);
```

Rozbicie składni: `LOCAL` = plik po stronie klienta, bez = plik na serwerze; `INTO TABLE` = tabela docelowa; `FIELDS TERMINATED BY` = separator pól (default `\t`); `LINES TERMINATED BY` = separator wierszy (default `\n`); `IGNORE 1 LINES` = pomiń nagłówek; lista kolumn na końcu = mapowanie pól z pliku, bez niej leci po kolei pól tabeli (wtedy `id` psuje kolejność).

### Pełna składnia LOAD DATA

```sql
LOAD DATA [LOW_PRIORITY | CONCURRENT] [LOCAL] INFILE 'file_name'
    [REPLACE | IGNORE]
    INTO TABLE tbl_name
    [CHARACTER SET charset_name]
    [{FIELDS | COLUMNS}
        [TERMINATED BY 'string']
        [[OPTIONALLY] ENCLOSED BY 'char']
        [ESCAPED BY 'char']
    ]
    [LINES
        [STARTING BY 'string']
        [TERMINATED BY 'string']
    ]
    [IGNORE number {LINES | ROWS}]
    [(col_name_or_user_var,...)]
    [SET col_name = expr,...];
```

## Lekcja 6 — Klucze główne (PRIMARY KEY)

### Najważniejsze zasady

- Klucz główny jednoznacznie identyfikuje wiersz: jest unikalny i nie dopuszcza NULL.
- Tabela ma najwyżej jeden PRIMARY KEY, ale może on obejmować jedną kolumnę (klucz prosty) albo kilka (klucz złożony).
- Przy kluczu złożonym unikalna jest kombinacja wartości, nie każda kolumna oddzielnie.
- PRIMARY KEY tworzy indeks. AUTO_INCREMENT jest osobnym mechanizmem generowania numerów, nie warunkiem istnienia klucza.
- Przed dodaniem klucza do istniejącej tabeli trzeba usunąć duplikaty i NULL w jego kolumnach.

### Tworzenie, dodawanie i usuwanie

Poniższe warianty są niezależnymi przykładami składni MySQL.

```sql
CREATE TABLE osoby_pk (
    id INT NOT NULL PRIMARY KEY,
    nazwisko VARCHAR(50) NOT NULL
);

CREATE TABLE uczestnictwo (
    osoba_id INT NOT NULL,
    kurs_id INT NOT NULL,
    PRIMARY KEY (osoba_id, kurs_id)
);

ALTER TABLE osoby_pk DROP PRIMARY KEY;
ALTER TABLE osoby_pk ADD PRIMARY KEY (id);
SHOW INDEX FROM osoby_pk;
```

W MySQL indeks klucza głównego ma nazwę PRIMARY. Nie należy przenosić składni DROP CONSTRAINT dla klucza głównego z innych systemów. Usunięcie klucza może wymagać wcześniejszego rozwiązania zależności FK lub AUTO_INCREMENT. Nazwy tabel zapisujemy bez apostrofów albo w backtickach.

## Lekcja 7 — Indeksy

### Do czego służą

Indeks to struktura danych pomagająca odnaleźć wiersze bez przeglądania całej tabeli. Nie musi być osobnym plikiem. Pomaga przy WHERE, JOIN, ORDER BY, GROUP BY oraz niektórych MIN/MAX, jeśli jego układ odpowiada zapytaniu.

- Zajmuje miejsce i zwiększa koszt utrzymania danych podczas INSERT, DELETE i aktualizacji indeksowanych wartości.
- Dobór indeksów wynika z zapytań, nie z zasady „indeks na każdą kolumnę”.
- Mała liczba różnych wartości zwykle zmniejsza korzyści z samodzielnego indeksu, lecz nie wyklucza jego przydatności, np. w indeksie złożonym.
- UNIQUE wymusza regułę unikalności, a nie tylko poprawia wydajność. W MySQL unikalny indeks może dopuścić wiele NULL, jeżeli kolumna jest nullable.

### Rodzaje i składnia

- Zwykłe indeksy InnoDB i MyISAM wykorzystują struktury B-tree; MEMORY obsługuje także HASH.
- FULLTEXT służy do wyszukiwania tekstowego i jest obsługiwany również przez InnoDB.
- SPATIAL służy do danych przestrzennych. Nie jest to zwykły indeks B-tree.
- Limit 16 kolumn dotyczy jednego indeksu wielokolumnowego, nie wszystkich indeksowanych kolumn tabeli.

```sql
CREATE INDEX idx_customer_town ON customer (town);
ALTER TABLE customer ADD INDEX idx_customer_lname (lname);
SHOW INDEX FROM customer;
DROP INDEX idx_customer_town ON customer;
```

Przykład UNIQUE (tylko gdy unikalność numeru telefonu jest rzeczywistą regułą danych):

```sql
CREATE UNIQUE INDEX uq_customer_phone ON customer (phone);
```

### Kolejność kolumn

```sql
CREATE INDEX idx_players_name_surname ON players (name, surname);
```

Indeks odpowiada wyszukiwaniu po name lub po name i surname. Sam surname nie jest lewostronnym prefiksem tego indeksu; nie należy zakładać takiej samej efektywności. Optimizer może czasem wykorzystać skanowanie indeksu lub inne optymalizacje — sprawdzamy plan, nie zgadujemy.

Dla warunku nationality = 'Poland' AND age BETWEEN 25 AND 30 naturalnym kandydatem jest indeks (nationality, age): najpierw równość, później zakres.

```sql
CREATE INDEX idx_players_nationality_age ON players (nationality, age);
EXPLAIN SELECT * FROM players
WHERE nationality = 'Poland' AND age BETWEEN 25 AND 30;
```

## Lekcja 8 — Klucze obce i powiązania tabel

### Zasady FOREIGN KEY

Klucz obcy wymusza istnienie powiązanego rekordu nadrzędnego. Zwykle wskazuje PRIMARY KEY, ale może wskazywać odpowiedni klucz UNIQUE. W przykładach stosujemy InnoDB oraz zgodne typy po obu stronach, w tym zgodność UNSIGNED; dla tekstu także charset i collation.

Indeks po stronie dziecka musi zaczynać się od kolumn FK w odpowiedniej kolejności. InnoDB utworzy go automatycznie, jeśli brak odpowiedniego. Jawne indeksy ułatwiają kontrolę schematu. MyISAM nie wymusza FK.

### Akcje referencyjne

- ON DELETE CASCADE — usunięcie rodzica usuwa powiązane wiersze dziecka, nie inne rekordy nadrzędne.
- ON UPDATE CASCADE — zmiana wskazywanego klucza aktualizuje jego wartości w FK dziecka.
- RESTRICT i NO ACTION — w InnoDB blokują operację naruszającą istniejące powiązania; kontrola nie jest odraczana.
- SET NULL — ustawia FK dziecka na NULL; wymaga nullable kolumn, więc nie nadaje się do kolumn będących częścią PK.
- SET DEFAULT — nie jest obsługiwane jako działająca akcja FK przez InnoDB.

### Przykład — gracze i zespoły

```sql
CREATE TABLE players (
    id INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    firstname VARCHAR(30)
) ENGINE=InnoDB;

CREATE TABLE teams (
    id INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(30) NOT NULL
) ENGINE=InnoDB;

CREATE TABLE players_to_teams (
    team_id INT UNSIGNED NOT NULL,
    player_id INT UNSIGNED NOT NULL,
    PRIMARY KEY (team_id, player_id),
    INDEX idx_ptt_player (player_id),
    CONSTRAINT fk_ptt_player FOREIGN KEY (player_id)
        REFERENCES players (id)
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT fk_ptt_team FOREIGN KEY (team_id)
        REFERENCES teams (id)
        ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB;
```

To relacja wiele do wielu. Dodanie UNIQUE(player_id) ograniczyłoby gracza do jednego zespołu. Usunięcie zespołu usuwa jego powiązania, a nie graczy.

Usuwanie konkretnego FK (osobny przykład, nie część tworzenia schematu):

```sql
ALTER TABLE players_to_teams DROP FOREIGN KEY fk_ptt_player;
```

Przy FK złożonym kolejność kolumn musi odpowiadać kluczowi rodzica, np. FOREIGN KEY (product_category, product_id) REFERENCES product(category, id). Dodanie FK do istniejących danych nie uda się, jeżeli są już osierocone rekordy.

## Lekcja 9 — CHECK i asercje

### Ograniczenia wartości

CHECK sprawdza warunek przy zapisie danych. FALSE powoduje naruszenie ograniczenia; TRUE albo UNKNOWN (np. przez NULL) jest dopuszczalne. Dlatego CHECK(cena >= 0) nie zastępuje NOT NULL.

Przykłady są przygotowane dla MySQL 8.4. W MySQL CHECK jest egzekwowany od 8.0.16; starsze wersje mogły przyjąć składnię, ale ignorować warunek. MariaDB wprowadziła obsługę CHECK w 10.2.1.

```sql
CREATE TABLE osoby_check (
    id INT NOT NULL PRIMARY KEY,
    nazwisko VARCHAR(100) NOT NULL,
    miasto VARCHAR(100),
    CONSTRAINT chk_osoby_id CHECK (id > 0)
);

ALTER TABLE osoby_check
ADD CONSTRAINT chk_osoby_miasto CHECK (miasto = 'Sandnes');

SHOW CREATE TABLE osoby_check;

ALTER TABLE osoby_check DROP CHECK chk_osoby_miasto;
```

Warunek obejmujący kilka kolumn zapisujemy jako ograniczenie tabeli, np. CHECK (data_zwrot >= data_wyp). Dodawanie CHECK sprawdza również istniejące dane. Nie używaj NOT ENFORCED, jeżeli ograniczenie ma odrzucać błędne wartości.

### Asercje a CHECK

Asercja standardu SQL jest ograniczeniem na poziomie schematu, potencjalnie obejmującym wiele tabel. Nie należy utożsamiać CREATE ASSERTION z tabelowym CHECK. Poniższy zapis ilustruje standard, nie jest skryptem do wykonania w MySQL 8.4:

```sql
CREATE ASSERTION poprawne_ceny
CHECK (NOT EXISTS (SELECT 1 FROM towar WHERE cena_jedn < 0));
```

Sam odnośnik do podręcznika SQL-99 na stronie MariaDB nie potwierdza obsługi CREATE ASSERTION przez serwer. Dla pojedynczego wiersza stosujemy CHECK, dla powiązań FK; reguły między tabelami wymagają innego rozwiązania, np. właściwie zaprojektowanych triggerów i transakcji.

W źródłowym przykładzie „cena IS NOT NULL OR cena >= 0” ujemna niepusta cena przechodziłaby test. Przykład ORDERS/RESULTS odwołuje się też do niezdefiniowanej kolumny DateReported — nie jest gotowym rozwiązaniem.

```sql
CREATE TABLE customer (
    customer_id INT NOT NULL AUTO_INCREMENT,
    title CHAR(4),
    fname VARCHAR(32),
    lname VARCHAR(32) NOT NULL,
    addressline VARCHAR(64),
    town VARCHAR(32),
    zipcode CHAR(10) NOT NULL,
    phone VARCHAR(16),
    PRIMARY KEY (customer_id)
) ENGINE=InnoDB AUTO_INCREMENT=17 DEFAULT CHARSET=utf8mb4;

CREATE TABLE item (
    item_id INT NOT NULL AUTO_INCREMENT,
    description VARCHAR(64) NOT NULL,
    cost_price DECIMAL(7,2),
    sell_price DECIMAL(7,2),
    PRIMARY KEY (item_id)
) ENGINE=InnoDB AUTO_INCREMENT=13 DEFAULT CHARSET=utf8mb4;

CREATE TABLE barcode (
    barcode_ean CHAR(13) NOT NULL,
    item_id INT NOT NULL,
    PRIMARY KEY (barcode_ean),
    KEY idx_barcode_item (item_id),
    CONSTRAINT barcode_item_id_fk FOREIGN KEY (item_id)
        REFERENCES item (item_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE orderinfo (
    orderinfo_id INT NOT NULL AUTO_INCREMENT,
    customer_id INT NOT NULL,
    date_placed DATE NOT NULL,
    date_shipped DATE,
    shipping DECIMAL(7,2),
    PRIMARY KEY (orderinfo_id),
    KEY idx_orderinfo_customer (customer_id),
    CONSTRAINT orderinfo_customer_id_fk FOREIGN KEY (customer_id)
        REFERENCES customer (customer_id)
) ENGINE=InnoDB AUTO_INCREMENT=6 DEFAULT CHARSET=utf8mb4;

CREATE TABLE orderline (
    orderinfo_id INT NOT NULL,
    item_id INT NOT NULL,
    quantity INT NOT NULL,
    PRIMARY KEY (orderinfo_id, item_id),
    KEY idx_orderline_item (item_id),
    CONSTRAINT orderline_item_id_fk FOREIGN KEY (item_id)
        REFERENCES item (item_id),
    CONSTRAINT orderline_orderinfo_id_fk FOREIGN KEY (orderinfo_id)
        REFERENCES orderinfo (orderinfo_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE stock (
    item_id INT NOT NULL AUTO_INCREMENT,
    quantity INT NOT NULL,
    PRIMARY KEY (item_id),
    CONSTRAINT stock_item_id_fk FOREIGN KEY (item_id)
        REFERENCES item (item_id)
) ENGINE=InnoDB AUTO_INCREMENT=11 DEFAULT CHARSET=utf8mb4;
```

**2.** Dodaj ograniczenia sell_price >= 0, cost_price >= 0 i quantity od 1 do 100 w stock. Sprawdź ich dodanie i dopisz je do test.sql.

```sql
USE test;
ALTER TABLE item
    ADD CONSTRAINT chk_item_sell_price CHECK (sell_price >= 0),
    ADD CONSTRAINT chk_item_cost_price CHECK (cost_price >= 0);
ALTER TABLE stock
    ADD CONSTRAINT chk_stock_quantity CHECK (quantity BETWEEN 1 AND 100);

SHOW CREATE TABLE item;
SHOW CREATE TABLE stock;
```

INT zapewnia całkowity typ przechowywanych wartości, CHECK określa zakres. MySQL może konwertować wejściowe ułamki do INT, więc to nie jest walidacja oryginalnego tekstu wejścia. Ceny NULL produktu 12 pozostają dopuszczone, zgodnie ze zrzutem; CHECK nie oznacza NOT NULL.

Testy odrzucenia uruchamiane osobno:

```sql
UPDATE item SET sell_price = -1 WHERE item_id = 1;
UPDATE item SET cost_price = -1 WHERE item_id = 1;
UPDATE stock SET quantity = 101 WHERE item_id = 1;
UPDATE stock SET quantity = 0 WHERE item_id = 1;
```

Każde zapytanie powinno zgłosić naruszenie odpowiedniego CHECK. Nie dodawaj celowo błędnych testów do skryptu odtwarzającego bazę.

**3.** Wykonaj backup bazy przed zmianą cen i usuwaniem klientów.

Terminal (także fish), nie edytor SQL:

```bash
mysqldump -u root -p --single-transaction --no-tablespaces --databases test > test_backup.sql
```

Opcja --databases zapisuje także CREATE DATABASE i USE. Kontynuuj dopiero po poprawnym zakończeniu eksportu. W czasie dumpa nie zmieniaj struktury tabel.

**4.** Zmień wszystkie ceny w tabeli item na 10.

```sql
USE test;
SET @poprzedni_safe_updates = @@SESSION.sql_safe_updates;
SET SESSION sql_safe_updates = 0;
UPDATE item SET sell_price = 10.00, cost_price = 10.00;
SET SESSION sql_safe_updates = @poprzedni_safe_updates;
```

Zmiana obejmuje obie kolumny i wszystkie produkty, także wcześniejsze NULL. Ustawienie sesyjne obsługuje tryb Safe Updates w Workbench i jest przywracane.

**5.** Usuń wszystkich klientów z customer.

Samo DELETE FROM customer zostanie zablokowane przez FK zamówień. W tym ćwiczeniu usuwamy również wszystkie zamówienia i ich pozycje, od dzieci do rodziców. Nie wyłączamy FOREIGN_KEY_CHECKS i nie pozostawiamy osieroconych rekordów.

```sql
SET @poprzedni_safe_updates = @@SESSION.sql_safe_updates;
SET SESSION sql_safe_updates = 0;
START TRANSACTION;
DELETE FROM orderline;
DELETE FROM orderinfo;
DELETE FROM customer;
COMMIT;
SET SESSION sql_safe_updates = @poprzedni_safe_updates;
```

Jeżeli któraś instrukcja usuwania zwróci błąd, zatrzymaj wykonywanie, użyj ROLLBACK zamiast COMMIT i przywróć sql_safe_updates. Transakcja dotyczy DELETE, nie wcześniejszych poleceń DDL.

**6.** Sprawdź zmiany, wyświetlając dane z odpowiednich tabel.

```sql
SELECT item_id, description, cost_price, sell_price FROM item ORDER BY item_id;
SELECT * FROM customer;
SELECT * FROM orderinfo;
SELECT * FROM orderline;
SELECT COUNT(*) AS liczba_klientow FROM customer;
```

Oczekiwane: 12 produktów z obiema cenami 10.00, brak klientów, zamówień i pozycji zamówień. To wartości wynikające z skryptu, a nie pomiar wykonany na serwerze.

**7.** Przywróć bazę z kopii zapasowej.

Terminal, z katalogu zawierającego test_backup.sql:

```bash
mysql -u root -p < test_backup.sql
```

```sql

UNION ALL SELECT 'orderline', COUNT(*) FROM orderline

```
